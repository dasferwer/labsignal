# LabSignal

A/B-эксперименты с отдельной регистрацией назначения и фактического показа,
дедупликацией метрик, проверкой перекоса групп и заранее определённым анализом.
Поддерживаются фиксированный срок и ограниченный план последовательных проверок.

## Дизайн эксперимента

- SHA-256 от случайной соли эксперимента и ID пользователя стабильно назначает A/B
  с вероятностью 50/50. Назначение само по себе не считается показом.
- В одном пространстве `namespace` запрещены эксперименты с пересекающимися
  периодами. Разные пространства независимы по настройке, но их взаимодействия
  система не оценивает.
- Метрика принимается только после показа и в течение `outcome_seconds` от него.
  После закрытия окна новые события отклоняются. Повтор прежнего события безопасен;
  другое содержимое под тем же ID возвращает 409.
- Конверсия — наличие хотя бы одного события метрики у пользователя. Выручка —
  сумма `amount` всех его уникальных событий. Пользователи без событий учитываются
  с нулевой конверсией и выручкой.
- Для анализа используются только показы с завершённым окном результатов.
  Перед фиксацией выборки сервис дожидается начатых транзакций записи метрик.

## Статистические методы

Конверсия проверяется двусторонним точным тестом Фишера, выручка — тестом Уэлча.
Два p-value корректируются методом Холма. SRM проверяется точным биномиальным
тестом против 50/50; при p < 0,001 вывод о значимости блокируется.

Для CUPED сначала регистрируется независимый пилот через `POST /pilots`:
20–10 000 пар `pre_value` и `revenue`, завершившихся до начала эксперимента.
Сервис вычисляет `theta = cov(pre_value, revenue) / var(pre_value)` и сохраняет
неизменяемый снимок с SHA-256. Эксперимент ссылается на `pilot_id`;
произвольный ненулевой `theta` без пилота запрещён. Анализируется
`revenue - theta * pre_value`; пилот не пересчитывается по текущим результатам.
`pre_period_end` должен быть не позже начала эксперимента, повторный показ
не может изменить значение ковариаты или её период.

При регистрации сохраняется протокол: параметры, метод назначения, метрики,
правило множественных проверок и SHA-256. Подтверждающие выводы разрешены,
только если протокол зарегистрирован до начала эксперимента. Исторические
эксперименты можно загрузить, но оба флага значимости остаются ложными;
эффекты и p-value в них имеют только описательный смысл.

Отчёт включает консервативные интервалы эффекта с поправкой на две метрики
и запланированные проверки. Для конверсии используются интервалы Уилсона,
для выручки — интервал Уэлча. Если дисперсия выручки в обеих группах нулевая,
интервал отсутствует, `variance_supported=false`, p-value=1: различие констант
не превращается в статистически подтверждённый эффект.

В режиме `fixed` до конца эксперимента и окна результатов p-value не выдаются.
После этого сохраняется неизменяемый отчёт. В режиме `planned` заранее задаются
размеры групп, например `[100,200,400]`: используются первые N зрелых показов
каждого варианта. Каждая из K проверок получает alpha=0,05/K; внутри неё применяется
Холм для двух метрик. Сумма бюджетов не больше 0,05: это консервативная схема
Бонферрони по заранее заданным проверкам, а не произвольное непрерывное наблюдение.
Повтор просмотра того же этапа возвращает сохранённый отчёт.

Для Уэлча контроль ошибок приблизительный и зависит от свойств данных.
Тяжёлые хвосты, зависимые наблюдения и ошибочные исходные ковариаты требуют другого
дизайна или дополнительной проверки; результат симуляции не заменяет эти условия.

## Запуск и API

```sh
docker compose up --build -d
curl -H 'X-API-Key: local-demo-key' http://localhost:8098/health
uv sync --frozen
uv run python -m scripts.demo
```

Демо выполняет назначение, показ, метрику, проверку запрета преждевременного
вывода и окончательный отчёт через HTTP. Оно занимает около 14 секунд.
Это функциональная демонстрация с маленькой выборкой, не полноценный эксперимент.

Все операции требуют `X-API-Key`; схемы запросов находятся на `/docs`.

- `POST /pilots`: `ended_at`, `rows` с полями `pre_value` и `revenue`.
- `POST /experiments`: `namespace`, `starts_at`, `ends_at`, `outcome_seconds`,
  `mode` (`fixed`/`planned`), `looks`, необязательный `pilot_id`.
- `POST /experiments/{id}/assign`: `user_id`; возвращает вариант.
- `POST /experiments/{id}/expose`: `user_id`, `pre_value`, `pre_period_end`.
- `POST /experiments/{id}/metrics`: UUID `id`, `user_id`, неотрицательный `amount`.
- `GET /experiments/{id}/results`: статус сбора либо сохранённый отчёт с эффектами,
  исходными и скорректированными p-value, SRM и составом выборки.

Дата начала и окончания должна иметь часовой пояс. Настройки эксперимента
неизменяемы; изменение методики требует нового эксперимента.

## Проверки и симуляции

```sh
cp .env.example .env
set -a
. ./.env
set +a
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv run python -m scripts.simulate
```

Тесты используют временные схемы PostgreSQL. Проверяются повторы, фактические
показы, закрытие окна, перекрытие экспериментов, запрет будущей ковариаты,
неизменяемость отчёта и протокола, запрет подтверждающих выводов задним числом,
конкурентные повторы метрик, интервалы, бюджет проверок, SRM и CUPED.
Симуляция с seed=42 выполняет по 400 экспериментов без эффекта и с изменением
конверсии с 15% до 25%, по 600 пользователей в группе. Для частоты выводов
приводится биномиальный доверительный интервал. CI выполняет тесты, симуляции
и полный сценарий через Docker API.

## Структура и ограничения

Python 3.11+, FastAPI, PostgreSQL 17, NumPy, SciPy. `stats.py` реализует анализ,
`api.py` — жизненный цикл и фиксацию отчётов, `db.py` — схему.

Два варианта, две фиксированные метрики, без кластерной рандомизации, атрибуции
между устройствами, удаления ботов и внешних источников. ID пользователя и
подлинность фактического показа обеспечивает вызывающая сторона.
Ковариата и пилот проверяются по заявленным датам, но их происхождение и
независимость сервис доказать не может. Выборка загружается в память, автоматической очистки истории нет.

Тесты и симуляции используют синтетические данные. Демо-пароль и API-ключ
предназначены для localhost. Остановка: `docker compose down`, том сохраняется.
Методы: [SciPy](https://docs.scipy.org/doc/scipy/reference/stats.html),
[CUPED](https://www.microsoft.com/en-us/research/articles/deep-dive-into-variance-reduction/).
